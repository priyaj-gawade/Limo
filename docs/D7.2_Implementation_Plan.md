## 2. Resolutions to User Review & The 5 MUST-FIX Items

### 2.1 MUST-FIX 1: Elimination of Scope Contradiction on Content Verification
- **Issue**: The original draft simultaneously stated "No Content Verification / No Native Save Yet" and had `AutomationRunner` perform DOM inspection and fail with `ZERO_CONTENT_GENERATED`.
- **Resolution**:
  - **D7.2 Boundary**:
    1. Create hidden background WebContentsView (1280×800 offscreen desktop viewport).
    2. Invoke existing native `AgentLoop`.
    3. Native skill executes.
    4. Editor/model receives mutations (or agent execution signals for PDF).
    5. Observe `AgentLoop` completion (`events.onDone` settles with `!cancelled`).
    6. Runner records substate `AGENT_COMPLETED`.
    7. **Zero semantic validation, zero disk saving, zero early D7.4 verification logic in D7.2.**
  - **D7.4 Boundary**:
    1. Editor/model content validity check (semantic verification).
    2. Execute native save workflow (`saveDocxNew`, `slides:save`, `sheets:save`).
    3. Validate real generated file on disk.

### 2.2 MUST-FIX 2: Large Image Handling & Separation from JSON Request Payload
- **Issue**: Images must never be base64-encoded into the HTTP JSON control message, which would risk exceeding D7.1's 1 MB control request limit.
- **Resolution**:
  - **Limo HTTP Request**: Sends strictly an `AutomationAttachmentReference` containing `storage_ref` (the absolute or sandboxed local path), `filename`, and `mime_type`. The HTTP request body remains a tiny control message (< a few KB).
  - **Main Process**: Validates path existence and safety on local disk.
  - **Headless Renderer**: The renderer resolves `storage_ref` locally using GenOffice's existing `window.desktop.readAttachmentImage(path)` (or equivalent) to produce in-memory `AgentImage` (`{ base64, mime }`) immediately before calling `AgentLoop.run(instruction, images)`.
  - **Zero raw bytes over the HTTP wire.**

### 2.3 MUST-FIX 3: Single Job System (Macro Status vs. Runner Substate)
- **Issue**: `AutomationRunnerState` must not become a competing secondary job system that drifts from `AutomationJobManager`.
- **Resolution**:
  - `AutomationJobManager` remains the **sole authoritative job state machine**:
    - `queued` → `generating` → `completed` (or `failed` / `cancelled`).
  - `AutomationRunner` owns an **execution substate** active only while `job.status === 'generating'`:
    - `STARTING`: view allocation, URL load, renderer handshake.
    - `RUNNING_AGENT`: `AgentLoop.run()` active, streaming turns and tool calls.
    - `AGENT_COMPLETED`: `AgentLoop` successfully settled via `onDone`.
  - The substate is published cleanly via `job.progress.substate` and cannot diverge from the macro status.

### 2.4 MUST-FIX 4: Non-Zero Hidden Viewport (Preventing 0×0 Layout Collapse)
- **Issue**: Setting bounds to `0,0,0,0` collapses editors that rely on viewport dimensions for canvas layout, text metrics, and virtualized grids.
- **Resolution**:
  - Source inspection proves:
    - **Slides**: Layout tree is laid out against reference viewport width `FIT_WIDTH = 1280` ([`app-constants.ts:2`](file:///c:/Users/Admin/Downloads/LIMO/external/GenOffice/apps/slides/src/renderer/app-constants.ts#L2)).
    - **Sheets**: Univer virtualized grid needs non-zero container dimensions to calculate row heights and column positions.
    - **Docs**: ProseMirror pagination and `AiPanel` width clamps expect normal window widths ([`AiPanel.tsx:117`](file:///c:/Users/Admin/Downloads/LIMO/external/GenOffice/apps/docs/src/renderer/ai/AiPanel.tsx#L117)).
    - **PDF**: PDF.js canvas rendering requires viewport aspect ratio.
  - **Architecture**:
    - Assign standard desktop content bounds: `{ x: 0, y: 0, width: 1280, height: 800 }` (or matching `shellWindow.getContentBounds()`).
    - Keep `view.setVisible(false)` strictly active.
    - Result: Chromium renders offscreen at 1280×800. Viewport coordinates and DOM dimensions are 100% valid, but the view remains completely invisible, draws nothing to the display, and cannot capture mouse or keyboard events.

### 2.5 MUST-FIX 5: Single Authoritative GenOffice Attachment Path
- **Issue**: Avoid creating a duplicate attachment subsystem for automation.
- **Resolution**:
  - **Images** (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`):
    - Converted to `AgentImage[]` via GenOffice's existing `readAttachmentImage(path)` and passed as multimodal vision input directly into `AgentLoop.run(instruction, images)`.
  - **Text & Data Documents** (`.docx`, `.xlsx`, `.pdf`, `.csv`, `.tsv`, `.txt`, `.json`, etc.):
    - Registered directly into GenOffice's existing `createFilesSkill(availableAttachments)`. The skill automatically builds the attachment manifest into the model context and exposes the existing `read_attachment(index, offset)` tool backed by `files:read` IPC.
  - **Zero new attachment tools or duplicate storage layers.**

## 4. D7.2 Architecture & Component Specification

### 4.1 Headless View Lifecycle Manager (`AutomationViewManager`)

The `AutomationViewManager` resides in the Electron Main process and manages the creation and teardown of background `WebContentsView` instances.

```typescript
export class AutomationViewManager {
  private activeView: WebContentsView | null = null
  private activeWcId: number | null = null

  constructor(private readonly shellWindow: BrowserWindow) {}

  /**
   * Creates a background WebContentsView for the requested format.
   * Viewport is set to standard 1280x800, but setVisible(false) keeps it invisible.
   */
  public async createHeadlessView(format: AutomationFormat): Promise<{ view: WebContentsView; webContentsId: number }> {
    if (this.activeView) {
      throw new Error('CONCURRENCY_VIOLATION: A headless view is already active')
    }

    let view: WebContentsView
    switch (format) {
      case 'document':
      case 'advisory':
      case 'summary':
        view = createDocsView(undefined)
        break
      case 'presentation':
        view = createSlidesView(undefined)
        break
      case 'spreadsheet':
        view = createSheetsView({ includeAiHandlers: true })
        break
      case 'pdf':
        view = createPdfView(undefined)
        break
      default:
        throw new Error(`UNSUPPORTED_FORMAT: ${format}`)
    }

    // Attach as hidden child view with healthy viewport dimensions
    this.shellWindow.contentView.addChildView(view)
    view.setBounds({ x: 0, y: 0, width: 1280, height: 800 })
    view.setVisible(false) // 100% invisible, does not draw to screen, does not take mouse input

    this.activeView = view
    this.activeWcId = view.webContents.id

    return { view, webContentsId: view.webContents.id }
  }

  public destroyActiveView(): void {
    if (!this.activeView) return
    try {
      this.shellWindow.contentView.removeChildView(this.activeView)
      if (!this.activeView.webContents.isDestroyed()) {
        this.activeView.webContents.close()
      }
    } catch {
      /* fail-safe teardown */
    } finally {
      this.activeView = null
      this.activeWcId = null
    }
  }
}
```

#### Isolation Guarantees:
- **Never Added to `TabManager.tabs`**: Tab strip never renders an automation tab.
- **Never Passed to `TabManager.activateTab()`**: User's active tab remains active and focused.
- **Window Level Integrity**: Parented to `shellWindow` so standard Electron IPC, Web Workers, and GPU rasterization work normally without displaying any UI.

### 4.2 Job Runner & State Subsystem (`AutomationRunner`)

`AutomationRunner` executes a dequeued `AutomationJobRecord`. It operates cleanly inside the existing `AutomationJobManager` macro lifecycle:

```text
Macro State (AutomationJobRecord.status):
  queued ────────► generating ────────────────────────► completed (or failed / cancelled)
                         │
Execution Substate       ▼
(job.progress.substate): STARTING ──► RUNNING_AGENT ──► AGENT_COMPLETED
```

#### Runner Execution Flow:
1. **STARTING**:
   - `jobManager` sets `job.status = 'generating'`.
   - `runner` sets `job.progress = { substate: 'STARTING', current_turn: 0, max_turns: 100, message: 'Initializing headless view' }`.
   - `viewManager.createHeadlessView(job.format)` creates view.
   - Waits for renderer handshake (`automation:renderer-ready`) with a 15-second timeout guard.
2. **RUNNING_AGENT**:
   - `runner` updates `job.progress.substate = 'RUNNING_AGENT'`.
   - Resolves attachment references (`AutomationAttachmentReference[]`).
   - Dispatches `automation:start-agent` IPC to renderer with `{ job_id, instruction, options, attachments }`.
   - Listens to `automation:agent-progress`: updates `job.progress.current_turn`, `last_tool`, `message`.
   - Listens for `cancellation_requested`: if flagged, dispatches `automation:agent-cancel` to renderer.
3. **AGENT_COMPLETED**:
   - Renderer's `AgentLoop` settles via `onDone({ cancelled: false })`.
   - Renderer sends `automation:agent-done` IPC to Main.
   - `runner` updates `job.progress.substate = 'AGENT_COMPLETED'`.
   - `runner` concludes execution. In D7.2, `job.status` transitions to `completed` (with `artifact: null`, as file persistence is D7.4).
   - `viewManager.destroyActiveView()` tears down the background view.

### 4.4 Main ↔ Renderer Automation IPC Contract

To keep existing editor UI code clean, we define a small, surgical automation bridge.

#### Preload Exposure (`window.automationBridge`):
Exposed in `apps/docs`, `apps/slides`, `apps/sheets`, `apps/pdf` via `contextBridge`:
```typescript
export interface AutomationBridge {
  signalReady: (format: string) => void
  onStartAgent: (handler: (payload: AutomationStartAgentPayload) => void) => () => void
  onCancelAgent: (handler: () => void) => () => void
  sendProgress: (progress: AutomationProgressPayload) => void
  sendDone: (result: AutomationDonePayload) => void
  sendError: (error: AutomationErrorPayload) => void
}
```

#### Renderer Automation Hook (`useAutomationAgent`):
Mounted in each editor runtime:
```typescript
export function useAutomationAgent({ format, loop, getEditorReady }: AutomationHookProps) {
  useEffect(() => {
    const bridge = window.automationBridge
    if (!bridge) return

    // 1. Signal ready once editor is fully mounted
    if (getEditorReady()) {
      bridge.signalReady(format)
    }

    // 2. Handle start command
    const unsubStart = bridge.onStartAgent(async (payload) => {
      try {
        // Collect multimodal images locally via existing desktop API
        const images: AgentImage[] = []
        if (payload.attachments) {
          const imageAtts = payload.attachments.filter(a => a.type === 'image')
          for (const att of imageAtts) {
            const res = await window.desktop.readAttachmentImage(att.storage_ref)
            if (res.ok && res.base64 && res.mime) {
              images.push({ base64: res.base64, mime: res.mime })
            }
          }
        }

        // Run existing native AgentLoop
        loop.run(payload.instruction, images.length > 0 ? images : undefined)
      } catch (err) {
        bridge.sendError({
          job_id: payload.job_id,
          code: 'INITIALIZATION_FAILED',
          message: err instanceof Error ? err.message : String(err),
        })
      }
    })

    // 3. Handle cancel command
    const unsubCancel = bridge.onCancelAgent(() => {
      loop.cancel()
    })

    return () => {
      unsubStart()
      unsubCancel()
    }
  }, [format, loop, getEditorReady])
}
```
