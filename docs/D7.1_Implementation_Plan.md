## 1. Executive Summary & Objective

The objective of **Phase D7.1** is to establish a secure, lightweight, reliable **local control interface** within GenOffice's Electron Main Process to receive and manage transformation generation requests from Limo.

D7.1 builds a **boring, reliable localhost HTTP/JSON control server** using standard `node:http` that:
1. Listens strictly on IPv4 loopback `127.0.0.1:<port>`.
2. Validates incoming transformation contracts against strict runtime schemas with payload size bounds.
3. Manages an in-memory, process-local FIFO job queue with concurrency ceiling of 1.
4. Exposes discovery metadata (`host`, `port`, `token`, `pid`, `protocol_version`) in a user-restricted local file.
5. Provides health, status, generation submission, and cancellation endpoints.
6. Defines clear cancel semantics (immediate dequeue for `QUEUED`; cancellation signal flag for active `GENERATING` delegated to D7.2).
7. Handshakes cleanly with Phase D7.2 via an in-memory runner callback API, **without creating any renderer or WebContentsView in D7.1**.

### Recommended D7.1 Flow
```text
Limo Agent / EngineRouter
         │
         ▼
POST /api/v1/generate
         │
         ▼
Validate token + runtime payload + size limit
         │
         ▼
Create GenOffice automation job (status: queued)
         │
         ▼
Return 202 Accepted + job_id
         │
         ▼
D7.2 runner later consumes queued job (deferred)
```

### Strict Non-Negotiable Constraints
- **Zero Python document rendering**: No python-pptx, python-docx, openpyxl generation.
- **Zero UI automation**: No mouse clicks, no keystroke simulation, no accessibility scraping.
- **Zero renderer creation in D7.1**: D7.1 is strictly the Main-process HTTP control interface and queue. View/renderer allocation is strictly D7.2/D7.3.
- **Independence**: Normal GenOffice homescreen and manual editing remain 100% functional and unhindered.

## 3. Defense-in-Depth Security Architecture (Must-Fix #2 & #3)

Rather than relying on Host-header checking alone, D7.1 enforces a layered defense-in-depth security boundary:

```text
Incoming Request
      │
      ├─► 1. Loopback Binding Guard: Only accept connections from 127.0.0.1 (never 0.0.0.0).
      │
      ├─► 2. Host-Header Verification: Host header MUST match 127.0.0.1:<port> or localhost:<port>.
      │      Rejects external rebinding attempts with HTTP 403 Forbidden.
      │
      ├─► 3. Cryptographic Token Authentication: All mutating routes require valid X-GenOffice-Token.
      │      Token is 32 cryptographically random bytes (crypto.randomBytes(32).toString('hex')).
      │      Rejects missing/invalid tokens with HTTP 401 Unauthorized.
      │
      ├─► 4. Payload Size Ceiling: Enforces strict 1 MB (1,048,576 bytes) request body limit.
      │      Rejects oversized requests immediately with HTTP 413 Payload Too Large.
      │
      ├─► 5. Strict Runtime Schema Validation: Unknown fields rejected; types and constraints enforced.
      │      Rejects malformed requests with HTTP 400 Bad Request.
      │
      └─► 6. Zero Arbitrary Command / Path Execution:
             Endpoints map strictly to predefined document generation workflows;
             save directory is strictly validated against permitted user paths.
```

### Token File Security & Permissions (Must-Fix #2)
- **Token Generation**: Generated at server startup via `crypto.randomBytes(32).toString('hex')`.
- **Directory Permissions**: `~/.genoffice/` directory is ensured with permissions `0o700` (POSIX user-only read/write/execute).
- **File Permissions**: `~/.genoffice/automation.json` is written with mode `0o600` (POSIX user-only read/write). On Windows, inherited ACLs restrict access to the active user profile.
- **Log Masking**: The token is strictly excluded from all application logs, debug messages, and console outputs (`[TOKEN_REDACTED]`).
- **Health Response Isolation**: `GET /api/v1/health` **never** exposes the token under any circumstances.

## 4. Discovery & Restart Lifecycle (Must-Fix #5 & #6)

### 4.1 Discovery File Content (`~/.genoffice/automation.json`)
The discovery file is **strictly a connection manifest**, NOT a source of truth for job or artifact state:

```json
{
  "host": "127.0.0.1",
  "port": 48123,
  "token": "e4a2c98d71b3...",
  "pid": 18492,
  "session_id": "sess_1726156800",
  "protocol_version": "1.0.0"
}
```

- **Not in discovery file**: Zero job records, zero queue states, zero artifact paths.
- **Source of Truth**:
  - Persistent job state lives in Limo's SQLite repository (`TransformationJob`).
  - Active runtime queue lives in GenOffice's in-memory `AutomationJobManager`.

### 4.2 Explicit Restart & Crash Semantics (Must-Fix #5)
- **In-Memory Queue**: The D7.1 job queue and state machine are **strictly process-local**.
- **Crash / Close Behavior**: If GenOffice closes, crashes, or is restarted:
  - Any active or queued jobs disappear from memory.
  - The discovery file is unlinked on clean exit (`before-quit`). On unclean exit, a stale PID check overwrites it on next launch.
- **Limo Responsibility**: Persistent recovery and job replay across process restarts belong to Limo's job lifecycle and future reliability phases. Limo detects GenOffice restarts (via PID change or reconnection failure) and re-enqueues jobs accordingly.

## 5. Runtime Request Validation (Must-Fix #1)

TypeScript interfaces do not validate JSON at runtime. D7.1 introduces a dedicated runtime validator (`automation-validator.ts`) executing before any payload reaches the queue.

### Request Body Constraints (`POST /api/v1/generate`)
1. **Size Ceiling**: Maximum 1 MB (1,048,576 bytes). Requests exceeding this return HTTP 413.
2. **Field Schema**:
   - `format` (or `type`): **Required string**. Must be one of:
     `"document"`, `"presentation"`, `"spreadsheet"`, `"pdf"`, `"markdown"`, `"html"`, `"advisory"`, `"summary"`.
   - `prompt`: **Required non-empty string**. Must have `trim().length >= 1` and `<= 50000`.
   - `job_id`: **Optional string**. If provided, must match `/^[a-zA-Z0-9_-]{1,128}$/`.
   - `project_id`: **Optional string**. If provided, must be string `<= 128` chars.
   - `session_id`: **Optional string**. If provided, must be string `<= 128` chars.
   - `canonical_id`: **Optional string**. If provided, must be string `<= 128` chars.
   - `canonical_hash`: **Optional string**. If provided, must match `/^[a-fA-F0-9]{64}$/`.
   - `options`: **Optional object**. If present:
     - `title`: optional string `<= 256` chars, sanitized against path traversal (`..`, `/`, `\`).
     - `approx_pages`: optional integer `>= 1` and `<= 100`.
     - `theme`: optional string `<= 64` chars.
     - `audience`: optional string `<= 64` chars.
     - `tone`: optional string `<= 64` chars.
     - `detail_level`: optional string `<= 64` chars.
     - `save_directory`: optional string path. If provided, must exist and be writable.
     - `sections_outline`: optional array of strings.
     - `custom_metadata`: optional key-value object.
3. **Unknown Top-Level Fields**: Strict rejection. Any unrecognized top-level properties result in HTTP 400 Bad Request with a detailed validation error:
   ```json
   {
     "ok": false,
     "error": {
       "code": "VALIDATION_ERROR",
       "message": "Unrecognized field 'malicious_extra_field' in request payload",
       "field": "malicious_extra_field"
     }
   }
   ```

## 6. Job State Machine & Cancellation Semantics (Must-Fix #4)

### 6.1 State Machine
```text
  [QUEUED] ──────────► [GENERATING] ──────────► [COMPLETED]
     │                      │
     │                      ├──────────► [FAILED]
     │                      │
     │ (cancel)             │ (cancellation_requested flag)
     ▼                      ▼
  [CANCELLED]          [CANCELLED] (Final transition confirmed by D7.2 runner)
```

### 6.2 Precise Cancel Semantics
When `POST /api/v1/jobs/{job_id}/cancel` is invoked:

1. **If Job is in `QUEUED` State**:
   - Immediate cancellation.
   - Job is immediately dequeued from the pending array.
   - Status transitions to `CANCELLED`.
   - Returns HTTP 200 OK:
     ```json
     {
       "ok": true,
       "job_id": "job_01j7...",
       "status": "cancelled",
       "message": "Queued job cancelled before execution"
     }
     ```

2. **If Job is in `GENERATING` State**:
   - D7.1 registers the cancellation request by setting `cancellation_requested: true` on the job record.
   - **D7.1 does not force-kill the runner**: It does not guess whether or how the active `AgentLoop` can abort.
   - Returns HTTP 202 Accepted:
     ```json
     {
       "ok": true,
       "job_id": "job_01j7...",
       "status": "generating",
       "cancellation_requested": true,
       "message": "Cancellation signal registered; awaiting runner termination"
     }
     ```
   - In Phase D7.2, the runner checks `job.cancellation_requested` and signals `ai:stream-cancel` to the active loop, which then marks the final status as `CANCELLED`.

3. **If Job is in a Terminal State (`COMPLETED`, `FAILED`, `CANCELLED`)**:
   - Returns HTTP 409 Conflict:
     ```json
     {
       "ok": false,
       "error": {
         "code": "ILLEGAL_STATE_TRANSITION",
         "message": "Cannot cancel job in terminal state 'completed'"
       }
     }
     ```

4. **If Job is Not Found**:
   - Returns HTTP 404 Not Found.

## 8. Interface to Phase D7.2 (Native Agent Invocation)

In Phase D7.1, the job manager provides a clean callback hook for the future D7.2 runner:

```typescript
export interface AutomationRunner {
  (job: AutomationJobRecord): Promise<AutomationArtifact>;
}

export class AutomationJobManager {
  private runner: AutomationRunner | null = null;

  public setRunner(runner: AutomationRunner): void {
    this.runner = runner;
    // Process next queued job when runner attaches
    this.drainQueue();
  }

  public getRunner(): AutomationRunner | null {
    return this.runner;
  }
}
```

- **In Phase D7.1**: Jobs enter the queue, transition to `queued`, and remain queued unless cancelled or drained in unit tests.
- **In Phase D7.2**: D7.2 will register `setRunner(...)` to spawn the background view, run `AgentLoop`, and return the saved artifact.
- **Zero Renderer coupling**: D7.1 does not import or instantiate any renderer code or `WebContentsView`.

Using GenOffice's Vitest test runner (`npm run test -w @genoffice/shell`):

   - Payload > 1 MB returns 413 Payload Too Large.
4. **Runtime Schema Validation**:
   - Empty prompt returns 400 Bad Request.
   - Unsupported format returns 400 Bad Request.

   - Asserts `automation.json` is created with mode `0o600`.
   - Asserts `automation.json` contains only `host`, `port`, `token`, `pid`, `session_id`, `protocol_version`.
