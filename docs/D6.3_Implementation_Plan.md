# Implementation Plan — Phase D6.3: Generation Contracts & Native Output Adapters (Revised)

This revised plan incorporates the Karpathy review feedback, eliminating overclaims, establishing a single authoritative execution path, and defining explicit boundaries for generation contracts and native adapters.

---

## 1. Executive Summary & Architectural Flow

Phase D6 establishes the **Transformation & Generation Orchestration** layer.
The workflow is strictly ordered:

```text
User / Agent
    │
    ▼
TransformContractTool (Single Agent Entry Point)
    │
    ▼
TransformService
    │
    ├── D6.1 TransformationRequest (TransformationConfigResolver)
    │   └── Deterministic parameter reconciliation & boundary enforcement
    │
    ├── D6.2 OutputPlan & EngineRoute (OutputPlanner & EngineRouter)
    │   └── Format-to-engine routing directory & deliverable decomposition
    │
    └── D6.3 Contracts & Native Execution (EngineRouter & Adapters)
        │
        ├── [External Deliverables: DOCX, PPTX, XLSX, VIDEO]
        │   ├── GenerationContractBuilder produces versioned contracts
        │   │   ├── GenOfficePayload (designed for future D7 Electron automation)
        │   │   └── VideoEnginePayload (versioned contract designed for future D8 adapter)
        │   └── Physical dispatch remains blocked (is_implemented=False)
        │       └── Raises UnimplementedEngineError (Zero Fake Generation)
        │
        └── [Native Deliverables: MARKDOWN, HTML, LINKEDIN, TWITTER, SVG]
            ├── Native Adapters execute real in-process generation
            │   ├── Strictly derived from CanonicalContent
            │   ├── No new factual claims (evidence & citations preserved)
            │   ├── Deterministic structural formatting for D6.3
            │   ├── StorageService.save_artifact_file() -> Physical files
            │   └── ArtifactService.register_artifact() -> Real Artifacts
            └── Physical dispatch active (is_implemented=True)
```

## 2. Review Revisions & Architectural Decisions

Following the review feedback, the following 5 critical corrections are locked into this plan:

| # | Review Point | Resolution in this Revised Plan |
|---|---|---|
| **1** | **"Zero hallucination" claim is too strong** | Replaced across all models, adapters, and docs with: **"strictly derived from CanonicalContent + no new factual claims + source/evidence references preserved."** |
| **2** | **Native Social Adapter role (LLM vs. Deterministic)** | Explicitly defined: **Native adapter = deterministic formatting and structural composition.** For D6.3, LinkedIn and Twitter adapters synthesize strictly from canonical fields (`intent.core_narrative`, `facts`, `data_points`, `recommendations`, `entities`). If LLM writing/polish is needed later, it is a separate controlled upstream step, not entangled in the native adapter. |
| **3** | **OpenMontage parser claim** | Replaced "exact structured format expected by OpenMontage's script parser" with **"versioned contract designed for the future D8 adapter."** |
| **4** | **`ExecuteDeliverableTool` removal** | **Removed completely.** Execution remains strictly behind `TransformService`. The agent interacts solely via `TransformContractTool`, preventing duplicate execution paths. |
| **5** | **`base.py` abstraction** | Retained as justified: `BaseNativeAdapter` and `GeneratedContent` cleanly unify the 3 concrete adapter modules (`markdown_adapter.py`, `social_adapter.py`, `infographic_adapter.py`). |

## 3. User Review Required

> [!IMPORTANT]
> **Single Execution Flow**: The Limo Agent will **not** receive a new tool to execute deliverables directly. All transformations flow through `TransformContractTool` → `TransformService` → `EngineRouter`. This guarantees consistent logging, state transitions, and single-source-of-truth job management.

> [!IMPORTANT]
> **Deterministic Formatting Baseline**: All native deliverables (Markdown, HTML, LinkedIn post, Twitter thread, Infographic SVG) in D6.3 are produced through deterministic structural templates. They emit only grounded facts, data points, and context directly present in `CanonicalContent`.

## 4. Proposed Changes

### Component 1: Generation Contracts & Payloads (External Handoff)

#### [NEW] [generation_contracts.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/models/generation_contracts.py)
- `GenOfficeOptions`: Document options including title, approx_pages, theme, audience, tone, detail_level, save_directory, `canonical_id`, and `canonical_hash`.
- `GenOfficePayload`: Versioned contract designed for future D7 Electron automation:
  - `type`: "document" | "presentation" | "spreadsheet" | "pdf" | "markdown" | "html"
  - `prompt`: Grounded transformation prompt combining user instructions and canonical narrative
  - `project_id`, `session_id`
  - `options`: `GenOfficeOptions`
- `VideoScriptScene`: Scene index, visual_cue, narration_text, estimated_duration_seconds.
- `VideoEnginePayload`: **Versioned contract designed for the future D8 adapter**:
  - `title`: Working deliverable title
  - `script_blueprint`: `List[VideoScriptScene]` mapped from `CanonicalEvent` and `CanonicalFact`
  - `audio_config`: Voice profile, language, speech rate (MoneyPrinterTurbo TTS specification)
  - `visual_config`: Aspect ratio (16:9 / 9:16), visual style, subtitle overlay flags (OpenMontage specification)
  - `estimated_duration_seconds`: Total target duration
  - `source_provenance`: `canonical_id`, `canonical_hash`
- `TweetItem`: `tweet_number`, `text` (strictly <= 280 characters), `char_count`.
- `TwitterThreadPayload`: `topic`, `tweets: List[TweetItem]`, `total_tweets`.

#### [NEW] [contracts.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/contracts.py)
- `GenerationContractBuilder`:
  - `build_genoffice_payload(canonical, deliverable, config, project_id, session_id) -> GenOfficePayload`
  - `build_video_payload(canonical, deliverable, config) -> VideoEnginePayload`
  - Pure builder functions translating `(CanonicalContent, PlannedDeliverable, GenerationConfig)` into versioned contract payloads without invoking external binaries.

### Component 2: Native Output Adapters (In-Process Execution)

#### [NEW] [base.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/adapters/base.py)
- `GeneratedContent`: Value object containing `content_bytes: bytes`, `filename: str`, `file_format: str`, `stats: str`, and `metadata: Dict[str, Any]`.
- `BaseNativeAdapter`: Abstract base class enforcing:
  - `synthesize(canonical: CanonicalContent, deliverable: PlannedDeliverable, config: GenerationConfig) -> GeneratedContent`
  - `execute(canonical, deliverable, config, project_id, job_id, storage, artifact_svc) -> Artifact`:
    1. Calls `synthesize()`
    2. Writes bytes via `StorageService.save_artifact_file()`
    3. Registers asset via `ArtifactService.register_artifact()`
    4. Attaches provenance metadata (`canonical_id`, `canonical_hash`)

#### [NEW] [markdown_adapter.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/adapters/markdown_adapter.py)
- `NativeMarkdownAdapter` (`OutputFormat.MARKDOWN`):
  - Strictly derived from `CanonicalContent`, introducing no new factual claims.
  - Formats Title, Executive Summary, Situational Context, Grounded Facts with evidence tags, Claims with citations `[REF-X]`, Data Points Table, and Actionable Recommendations.
- `NativeHtmlAdapter` (`OutputFormat.HTML`):
  - Self-contained, responsive HTML5 document.
  - Clean embedded CSS, styled KPI cards, semantic fact callouts with evidence badges (`.badge-verified`, `.badge-weak`), and provenance footer.

#### [NEW] [social_adapter.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/adapters/social_adapter.py)
- `NativeSocialAdapter` (`OutputFormat.LINKEDIN` and `OutputFormat.TWITTER`):
  - **LinkedIn Mode**:
    - Deterministic structural formatting for D6.3.
    - Hook line tailored to audience, bulleted takeaways derived from facts, bold numerical proof points from data points, professional call-to-action, and curated hashtags from entities/topics.
  - **Twitter/X Mode**:
    - Multi-tweet thread output in structured JSON (`.json`) with each tweet strictly bounded to `<= 280` characters.
    - Numbered format (`1/N`), starting with hook/thesis, followed by data points, and ending with attribution.

#### [NEW] [infographic_adapter.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/adapters/infographic_adapter.py)
- `NativeInfographicAdapter` (`OutputFormat.INFOGRAPHIC`):
  - Generates standalone, valid vector SVG diagram (`.svg`, `viewBox="0 0 1200 800"`).
  - Executive layout: Header banner, 3-4 KPI stat cards (large numbers, metric units, labels), key findings list, entity badges, and SHA-256 provenance hash footer.

### Component 3: Engine Router & Execution Service Integration

#### [MODIFY] [engine_router.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transformation/engine_router.py)
- Update `ROUTING_TABLE`:
  - `MARKDOWN`: `is_implemented=True`
  - `HTML`: `is_implemented=True`
  - `LINKEDIN`: `is_implemented=True`
  - `TWITTER`: `is_implemented=True`
  - `INFOGRAPHIC`: `is_implemented=True`
  - `DOCUMENT`, `PRESENTATION`, `SPREADSHEET`, `ADVISORY`, `SUMMARY`, `PDF`, `VIDEO`: `is_implemented=False` (retained for D7 and D8).
- Update `dispatch(route, deliverable, canonical, config, project_id, job_id) -> Optional[Artifact]`:
  - If `route.is_implemented is True`: Dispatches to native adapter, persists file, registers `Artifact`, and returns it.
  - If `route.is_implemented is False`: Raises `UnimplementedEngineError(engine_type=..., target_phase=...)`.
- Add `build_contract(deliverable, canonical, config, project_id, session_id) -> Union[GenOfficePayload, VideoEnginePayload, Dict[str, Any]]`.

#### [MODIFY] [transform_service.py](file:///c:/Users/Admin/Downloads/LIMO/backend/app/services/transform_service.py)
- Add execution methods behind `TransformService`:
  - `execute_deliverable(deliverable_id: str, job_id: str) -> Artifact`
  - `execute_native_deliverables(job_id: str) -> List[Artifact]`
- Updates job state (`JobState.COMPLETED` if all deliverables are finished, or updates progress if external deliverables remain pending D7/D8).
- Zero second execution path: Agent interacts via existing `TransformContractTool`, which delegates directly to `TransformService`.
