## 1. Executive Summary & Core Objective

The objective of **Phase D7.4** is to bridge the gap between successful in-memory agent generation (`AGENT_COMPLETED`) and a **verified, structurally valid physical document on local disk** by producing and validating the **GenOffice-side `AutomationArtifact`**.

In Phases D7.2 and D7.3, the automation engine was intentionally frozen with `artifact = null`: the hidden background view was destroyed immediately upon receiving `automation:agent-done`, and any in-flight background autosaves were rolled back or aborted.

Phase D7.4 establishes the complete, deterministic pipeline from agent completion to validated disk artifact:

```text
         Phase D7.3
      AGENT_COMPLETED
            ↓
         Phase D7.4
      CONTENT_VERIFIED     (Editor model/store inspected; actual mutation data verified; tool counts NOT trusted blindly)
            ↓
        SAVE_STARTED       (Native GenOffice save/export API invoked; NO UI/mouse/keystroke simulation)
            ↓
         FILE_SAVED        (Physical filesystem flush confirmed via native save IPC Promise resolution)
            ↓
       FILE_VALIDATED      (Size > 0, SHA-256 computed, structural OpenXML / pdf-lib parsing passes)
            ↓
  Unified Convergent Teardown (Hidden WebContentsView closed, audio/timers detached, uncommitted backing files purged)
            ↓
    GenOffice AutomationArtifact Produced
            ↓
         Phase D7.5
    Limo Artifact Handoff  (Artifact transferred/referenced into Limo's Artifact system & Chat UI)
```

```text
            │                                                     │

            │                                                     │

            └──────────────────────────┬──────────────────────────┘
                                       ▼
                       [Structural pdf-lib Validation]
                                       ▼

```

#### Detailed Specification of Both Pathways:

1. **Pathway A (In-Place Modifications / Annotations)**:
   - **Trigger**: The prompt instructs the agent to modify, mark up, fill forms, or add content to the active document.
   - **Target File**: The pre-allocated blank PDF in `defaultSaveDir()` created during view allocation.
   - **Save Mechanism**: Renderer calls `await window.pdfApi.save({ path: filePath, ...editsPayload(edits, noteFlush) })`.
   - **Completion**: `pdfApi.save` Promise resolves `{ ok: true }`.
   - **Artifact**: Backing file path is marked `handle.fileCommitted = true` and returned.

2. **Pathway B (Standalone Creation via `create_document`)**:
   - **Trigger**: The prompt instructs the agent to generate a new standalone document (e.g. summary report, executive notes). Per `pdf-skill.ts:29`, the model chooses `create_document`.
   - **Target File**: `uniquePathIn(defaultSaveDir(), `${title}.pdf`)` created directly by Chromium headless print via `createAiDocument` (`docs-main.ts:3916`).
   - **Tracking Mechanism**: In `apps/pdf/src/renderer/ai/tools.ts:3593`, `executePdfTool` intercepts `deps.createDocument`. When it succeeds with `r.path`, it sets `createdDocumentPathRef.current = r.path`.
   - **At `onDone`**:
     - The renderer detects `createdDocumentPathRef.current !== null`.
     - It bypasses `pdfApi.save()` (no redundant blank file overwrite).
     - It emits `automation:file-saved` with `file_path: createdDocumentPathRef.current`.
     - The runner unlinks the unused pre-allocated blank backing file.
     - The standalone document is marked `handle.fileCommitted = true`, validated, and returned.

### 2.4 MUST-FIX #2: Strict Mutation-Based Content Verification (Zero Tool-Count Blind Trust)

**Problem Identified**: Previous rules permitted `runToolsRef.current.length > 0` as a content signal. Read-only operations (`search_text`, `read_pages`, `list_attachments`, `get_outline`) execute tools without modifying document state. Counting tool executions as "content generated" creates false positives.

**D7.4 Hardened Content Verification Rules**:

1. **Docs (`document` / `summary`)**:
   - `editor.state.doc.textContent.trim().length >= 20` characters.
   - AND `editor.state.doc.content.size > initialDocContentSizeRef.current`.
   - AND `editor.state.doc.childCount >= 1`.
   - Tool count is **ignored**.

2. **Slides (`presentation`)**:
   - `slidesRef.current.length >= 1` (at least 1 slide exists).
   - AND `totalNodes = slidesRef.current.reduce((acc, s) => acc + (s.nodes?.length || 0), 0) >= 1`.
   - AND at least one text or shape node contains non-empty text/geometry.
   - Tool count is **ignored**.

3. **Sheets (`spreadsheet`)**:
   - `lazyWorkbookRef.current !== null` (backing session mounted).
   - AND (`getActiveSheetInfo().knownAddresses.length > 0` OR `journalSize(lazyWorkbookRef.current.editJournal) > 0`).
   - AND `runMutatedRef.current === true`.
   - Tool count is **ignored**.

4. **PDF (`pdf`)**:
   - **Pathway A (In-Place)**:
     - `runMutatedRef.current === true` (only set to true when a modifying tool succeeds in `tools.ts`).
     - AND at least one mutation collection is non-empty:
       `textInserts.length > 0 || edits.length > 0 || noteFlush.drawings.length > 0 || formEdits.size > 0 || rotations.size > 0 || deleted.size > 0`.
   - **Pathway B (Standalone Creation)**:
     - `createdDocumentPathRef.current !== null`.
     - AND `existsSync(createdDocumentPathRef.current)`.
     - AND `statSync(createdDocumentPathRef.current).size > 1000`.
   - **Rejection Invariant**: If neither Pathway A mutations nor Pathway B output exists, content verification fails with `ZERO_CONTENT_GENERATED`, regardless of how many read/search tools were executed.

### 2.5 MUST-FIX #3: Deterministic Backing-File Tracking & Cleanup on All Failure Paths

Pre-allocating physical backing files for Sheets (`.xlsx`) and PDF (`.pdf`) is necessary for GenOffice's native save pipeline, but introduces the risk of leaving orphan blank files on disk if execution fails.

#### Deterministic Tracking & Cleanup Architecture:

1. **View Allocation Tracking**:
   - When `AutomationViewManager.createHiddenView` creates a backing file, it attaches tracking metadata to `activeHandle`:
     ```typescript
     handle.backingFilePath = filePath
     handle.fileCommitted = false
     ```
2. **Commit Condition**:
   - Only when `FILE_VALIDATED` successfully finishes in `AutomationExecutionRunner` is `handle.fileCommitted = true` marked.
3. **Convergent Unlink Guard (The `finally` Block)**:
   - In `AutomationExecutionRunner.execute()` unified `finally` block and `AutomationViewManager.destroyActiveView()`:
     ```typescript
     if (handle.backingFilePath && !handle.fileCommitted) {
       if (existsSync(handle.backingFilePath)) {
         try {
           unlinkSync(handle.backingFilePath)
           console.log(`[AutomationViewManager] Unlinked uncommitted backing file: ${handle.backingFilePath}`)
         } catch (err) {
           console.warn(`[AutomationViewManager] Failed to unlink backing file: ${handle.backingFilePath}`, err)
         }
       }
     }
     ```
4. **All Failure Paths Guaranteed Clean**:
   - **Agent error / crash**: `fileCommitted === false` -> backing file unlinked.
   - **Execution timeout**: `fileCommitted === false` -> backing file unlinked.
   - **Cancellation mid-run**: `fileCommitted === false` -> backing file unlinked.
   - **Content verification failure (`ZERO_CONTENT_GENERATED`)**: `fileCommitted === false` -> backing file unlinked.
   - **Save API failure (`SAVE_EXECUTION_FAILED`)**: `fileCommitted === false` -> backing file unlinked.
   - **Structural validation failure (`CORRUPT_FILE_GENERATED`)**: `fileCommitted === false` -> backing file and corrupt file unlinked.
   - **PDF Pathway B (`create_document`)**: Standalone PDF is committed; initial blank backing PDF is marked uncommitted and unlinked.

## 5. File Integrity Verification & Structural Parsing

Relying solely on file existence, file size, or magic bytes (`PK\x03\x04`, `%PDF-`) is insufficient to prove a generated document is structurally sound. D7.4 implements a dedicated validation module:  
[`apps/shell/src/main/automation-file-validator.ts`](file:///c:/Users/Admin/Downloads/LIMO/external/GenOffice/apps/shell/src/main/automation-file-validator.ts).

### 5.1 Verification Checklist

```typescript
export interface FileValidationResult {
  valid: boolean
  size_bytes: number
  sha256: string
  error?: string
  metadata?: Record<string, unknown>
}
```

1. **Existence & Size**:
   - `existsSync(filePath) === true`
   - `statSync(filePath).size >= MIN_FILE_SIZE_BYTES` (e.g. DOCX >= 2,000 bytes, PPTX >= 4,000 bytes, XLSX >= 3,000 bytes, PDF >= 500 bytes).
2. **Cryptographic Digest**:
   - SHA-256 computed via `createHash('sha256').update(buffer).digest('hex')`.
3. **Structural OpenXML Parsing (`JSZip`)**:
   - For DOCX, PPTX, XLSX:
     - `const zip = await JSZip.loadAsync(buffer)`
     - Verify `zip.file('[Content_Types].xml')` is present and parseable.
     - **Docs**: Verify `zip.file('word/document.xml')` exists and contains `<w:body>` with non-empty content.
     - **Slides**: Verify `zip.file('ppt/presentation.xml')` exists and `zip.file('ppt/slides/slide1.xml')` exists.
     - **Sheets**: Verify `zip.file('xl/workbook.xml')` exists and `zip.file('xl/worksheets/sheet1.xml')` exists.
4. **Structural PDF Parsing (`pdf-lib`)**:
   - For PDF:
     - `const pdfDoc = await PDFDocument.load(buffer)`
     - Verify `pdfDoc.getPageCount() >= 1`.
     - Verify page geometry: `page.getWidth() > 0 && page.getHeight() > 0`.

If structural parsing fails, the runner marks the job as `failed` with error code `CORRUPT_FILE_GENERATED`, unlinks the corrupted file, and does not return the artifact.

## 6. Filename & Path Generation Architecture

### 6.1 Safe Title Sanitization
To prevent path traversal, directory escapes, and invalid filesystem characters across Windows, macOS, and Linux:

```typescript
export function sanitizeTitle(rawTitle?: string): string {
  if (!rawTitle || typeof rawTitle !== 'string') return ''
  // Strip control characters, quotes, path separators, and reserved OS characters
  const cleaned = rawTitle
    .replace(/[<>:"/\\|?*\x00-\x1F]/g, ' ')
    .replace(/\s+/g, ' ')
    .trim()
  // Guard against dot-only or traversal tokens
  if (cleaned === '.' || cleaned === '..' || cleaned.length === 0) return ''
  // Truncate stem to safe length (max 80 chars)
  return cleaned.slice(0, 80)
}
```

### 6.2 Format-Specific Fallbacks & Extensions
```typescript
export function resolveSafeFileName(format: AutomationFormat, rawTitle?: string): string {
  const safe = sanitizeTitle(rawTitle)
  switch (format) {
    case 'document':
    case 'summary':
      return safe ? `${safe}.docx` : 'Untitled Document.docx'
    case 'presentation':
      return safe ? `${safe}.pptx` : 'Untitled Presentation.pptx'
    case 'spreadsheet':
      return safe ? `${safe}.xlsx` : 'Untitled Spreadsheet.xlsx'
    case 'pdf':
      return safe ? `${safe}.pdf` : 'Untitled PDF.pdf'
    default:
      return safe ? `${safe}.bin` : 'Untitled Document.bin'
  }
}
```

## 7. Failure Handling, Backing Cleanup & Cancellation Matrix

| Failure Scenario | Detection Point | Reaction & Cleanup | Resulting Job State | Error Code |
|---|---|---|---|---|
| **Zero Content Generated** | Post-`AgentLoop` content inspection in renderer | Abort save; emit `automation:agent-error`; unlink uncommitted backing file | `failed` | `ZERO_CONTENT_GENERATED` |
| **Invalid/Empty Model Output** | Renderer content validation checks | Abort save; emit `automation:agent-error`; unlink uncommitted backing file | `failed` | `EMPTY_EDITOR_MODEL` |
| **Save API Throws / Rejects** | Native save IPC Promise rejection | Catch error; emit `automation:agent-error`; unlink uncommitted backing file | `failed` | `SAVE_EXECUTION_FAILED` |
| **Save Exceeds Timeout** | Runner execution watchdog timer | Trigger cooperative cancel; escalate; unlink uncommitted backing file | `failed` | `EXECUTION_TIMEOUT` |
| **File Not Found on Disk** | Runner `existsSync(savedPath)` check | Teardown view; fail job; unlink uncommitted backing file | `failed` | `FILE_NOT_FOUND_AFTER_SAVE` |
| **Zero-Byte or Truncated File** | Runner file size threshold check | Unlink corrupted file & backing file; fail job | `failed` | `EMPTY_FILE_WRITTEN` |
| **Structural Parsing Corrupt** | Runner `JSZip` / `pdf-lib` parse rejection | Unlink corrupted file & backing file; fail job | `failed` | `CORRUPT_FILE_GENERATED` |
| **Cancellation During Save** | `job.cancellation_requested === true` | Cleanly abort/unlink uncommitted backing file; teardown | `cancelled` | `CANCELLATION_REQUESTED` |
| **Shell Window Closes Mid-Save** | `AutomationViewManager.onWindowClosing` | Force teardown view; unlink uncommitted backing file; fail job | `failed` | `SHELL_WINDOW_CLOSED` |

## 8. Non-Interference with Normal GenOffice Usage

Background automation must never disturb the human user interacting with GenOffice:
1. **Zero Keystroke / Focus Hijacking**:
   - `view.setVisible(false)` remains active throughout the entire save lifecycle.
   - Manual `Ctrl+S`, `Ctrl+O`, menu clicks, and window focus in visible tabs are 100% unaffected.
2. **Separate WebContents IDs**:
   - Hidden views operate under isolated `webContents.id`.
   - IPC channels and pending resolvers key strictly on `wc.id` and `job_id`.
3. **Audio Muting & Navigation Guards**:
   - Audio remains permanently muted (`setAudioMuted(true)`).
   - External navigation remains blocked (`will-navigate` guard).
4. **Independent View Lifecycle**:
   - The hidden view is allocated on-demand and destroyed strictly inside the runner's unified `finally` block.
