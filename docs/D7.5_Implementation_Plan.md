## 1. Executive Summary & Phase D7.5 Objective

### 1.1 Core Goal
The goal of **Phase D7.5** is to bridge the real physical documents generated and validated in Phase D7.4 back into Limo's conversational chat interface.

The user must immediately see the generated artifact in chat accompanied by a concise, safe subagent execution summary, inspect a real visual thumbnail of the generated document, click anywhere on the thumbnail to download the file, or click an Edit pill button to open the document directly in GenOffice.

### 1.2 Strict UI Boundaries & Anti-Bloat Rules
1. **NO Preview Canvas, Modal, or Drawer**: The artifact card does **not** include a slide-out preview drawer, preview modal, embedded iframe canvas, or dedicated preview route. The thumbnail itself is the sole visual element.
2. **NO Large Metadata / Provenance Panels**: SHA-256 hashes, cryptographic provenance, and raw AST outlines remain backend internal records. They are not displayed on the chat card.
3. **NO Fake Thumbnails**: If thumbnail capture fails or is not yet complete, a clean, styled format fallback is displayed. No synthetic placeholder images or mock screenshot assets are generated.
4. **NO Private Chain-of-Thought**: Only safe, concise, user-facing subagent progress and summaries (`execution_summary`) are rendered. Private model reasoning is strictly rejected by validation guards.
5. **No Production Code Modifications During Planning**: This document defines the architectural specification before execution.
6. **No Implementation of D7.6**: Full end-to-end multi-job stress testing belongs strictly to Phase D7.6.

## 3. Real Thumbnail Generation Strategy

### 3.1 Capturing the Rendered Frame in GenOffice
In GenOffice, automation jobs execute inside an offscreen child `WebContentsView` attached to `shellWindow`. At the completion of Phase D7.4, the document has been verified on disk (`FILE_VALIDATED`), but the `WebContentsView` has not yet been torn down.

In Phase D7.5, before invoking `releaseView()`, GenOffice captures the actual rendered document frame:

```typescript
// Inside apps/shell/src/main/automation-runner.ts, immediately following FILE_VALIDATED:
let thumbnailPath: string | undefined

try {
  // 1. Force microtask flush to ensure final layout paint is committed
  await new Promise((r) => setTimeout(r, 100))

  // 2. Capture real rendered page from WebContents
  const image = await wc.capturePage()

  // 3. Verify image is non-empty (avoid blank black frames)
  if (!image.isEmpty()) {
    const size = image.getSize()
    // Standardize to crisp 480px width preserving aspect ratio
    const targetWidth = 480
    const targetHeight = Math.round((size.height / size.width) * targetWidth)
    const resized = image.resize({ width: targetWidth, height: targetHeight, quality: 'better' })
    const thumbBuffer = resized.toPNG()

    // 4. Save thumbnail alongside the native document in defaultSaveDir
    thumbnailPath = `${fileSaved.file_path}.thumb.png`
    writeFileSync(thumbnailPath, thumbBuffer)
    console.log(`[AutomationExecutionRunner] Captured real thumbnail (${thumbBuffer.length} bytes): ${thumbnailPath}`)
  }
} catch (thumbErr) {
  console.warn('[AutomationExecutionRunner] Non-fatal thumbnail capture error:', thumbErr)
}
```

### 3.2 Authoritative Handoff Contract with Thumbnail
Update `external/GenOffice/apps/shell/src/main/automation-types.ts`:

```typescript
export interface AutomationArtifact {
  title: string
  file_format: string
  file_path: string
  thumbnail_path?: string       // Absolute path to real captured PNG thumbnail
  size_bytes?: number
  content_hash?: string
  metadata?: Record<string, unknown>
}
```

### 3.3 Clean Fallback State (Zero Fake Imagery)
If `image.isEmpty()` is true or thumbnail capture fails (e.g. headless environment with hardware acceleration disabled):
- `thumbnail_path` remains `undefined`.
- In Limo UI, the thumbnail container displays a clean, minimal document type card featuring the file extension badge (`.DOCX`, `.PPTX`, `.XLSX`, `.PDF`) and Lucide icon.
- **Never synthesize fake screenshot graphics, stock templates, or mock diagrams.**

## 4. Thumbnail Storage & Association with Limo Artifact

### 4.1 Sandboxed Storage Ingestion
When Limo's `genoffice_client` receives the completed job with `artifact.thumbnail_path`:
1. It reads the raw PNG bytes from `thumbnail_path`.
2. It verifies the image buffer starts with the standard PNG magic bytes (`0x89 0x50 0x4E 0x47`).
3. It ingests the thumbnail into Limo's sandboxed storage via:
   ```python
   storage_service.save_artifact_file(artifact.id, "thumbnail.png", thumb_bytes)
   ```
   This atomically persists the file to `data/artifacts/art_<id>/thumbnail.png`.
4. It records the internal reference in the `Artifact` metadata:
   ```python
   artifact.metadata["thumbnail_storage_ref"] = f"artifacts/{artifact.id}/thumbnail.png"
   artifact.metadata["has_thumbnail"] = True
   ```

### 4.2 Thumbnail Serving Endpoint
In `backend/app/api/v1/artifacts.py`:

```python
@router.get("/{artifact_id}/thumbnail")
async def get_artifact_thumbnail(artifact_id: str) -> Response:
    """Serve the verified real PNG thumbnail for a deliverable artifact."""
    artifact = artifact_service.get_artifact(artifact_id)
    thumb_ref = artifact.metadata.get("thumbnail_storage_ref")
    
    if not thumb_ref or not storage_service.file_exists(thumb_ref):
        return Response(status_code=status.HTTP_404_NOT_FOUND)
        
    content = storage_service.read_file(thumb_ref)
    return Response(
        content=content,
        media_type="image/png",
        headers={
            "Cache-Control": "public, max-age=86400, immutable",
            "Content-Type": "image/png",
        },
    )
```

### 6.3 Automatic Download Action
Clicking **anywhere** on `.artifact-thumbnail-frame` triggers the download:

```typescript
const handleDownload = (art: Artifact) => {
  const downloadUrl = `/api/v1/artifacts/${art.id}/download`;
  const link = document.createElement('a');
  link.href = downloadUrl;
  link.download = `${art.title.replace(/\s+/g, '_')}${art.fileFormat}`;
  document.body.appendChild(link);
  link.click();
  document.body.removeChild(link);
};
```
This hits the verified endpoint `GET /api/v1/artifacts/{id}/download`, which:
1. Re-validates the SHA-256 digest on disk.
2. Formats `Content-Disposition: attachment; filename="..."`.
3. Streams the real binary without path traversal.

## 10. Audit of Assumptions & Non-Negotiables

| Requirement | Status | Implementation Truth & Code Evidence |
|---|---|---|
| **NO preview canvas / drawer / modal** | STRICTLY EXCLUDED | Card is minimal: Title, badge, summary, `[ Edit ]`, `[ THUMBNAIL ]`. No modal or canvas code. |
| **Real rendered thumbnail only** | ENFORCED | Captured via `wc.capturePage()` at `FILE_VALIDATED`. If unavailable, clean format icon fallback. |
| **Thumbnail hover blur & dark overlay** | ENFORCED | CSS `filter: blur(4px) brightness(0.65)` + `background: rgba(0,0,0,0.45)`. |
| **Centered dark circular download button** | ENFORCED | Circular 44px icon button styled with `#141413`, subtle border, and white Lucide `Download`. |
| **Click anywhere on thumbnail downloads** | ENFORCED | `onClick` on `.artifact-thumbnail-frame` invokes `/api/v1/artifacts/{id}/download`. |
| **Edit button on the LEFT of thumbnail** | ENFORCED | Placed as `[ Edit ] [ THUMBNAIL ]` row in DOM and flex layout. |
| **Edit button is pill-shaped** | ENFORCED | Styled with `border-radius: var(--radius-pill)` matching Limo token system. |
| **Subagent summary without private CoT** | ENFORCED | Only public `execution_summary` is shown; `reject_chain_of_thought` strips private reasoning. |
| **D7.6 remains deferred** | ENFORCED | Multi-job concurrency and stress testing remain excluded until Phase D7.6. |
