## 1. Executive Summary

Phase D7.4 closes the critical gap between in-memory LLM agent completions and **verified, structurally valid physical documents on disk**. 

In previous phases (D7.2 and D7.3), the automation engine was intentionally frozen with `artifact = null`: hidden views were destroyed immediately upon `automation:agent-done`, and any in-flight background autosaves were aborted or untracked.

In **Phase D7.4**, we implemented the complete native document saving and validation lifecycle:
```text
      AGENT_COMPLETED       (Agent loop completes with tool turns & content change metrics)
             ↓
     CONTENT_VERIFIED       (Strict mutation verification: document length, child count, slide elements, cell count)
             ↓
        SAVE_STARTED        (Awaiting native editor save API invocation: saveDocxNew, slidesApi.save, saveWorkbookEdits, pdfApi.save)
             ↓
         FILE_SAVED         (Renderer-to-main IPC handshake confirms physical file written to defaultSaveDir)
             ↓
       FILE_VALIDATED       (JSZip OpenXML validation / pdf-lib AST parsing, SHA-256 checksum, minimum size verified)
             ↓
  Unified Convergent Teardown (Hidden WebContentsView closed, uncommitted backing files purged)
             ↓
   GenOffice AutomationArtifact Produced & Returned
```

## 2. Key Architecture Decisions & Reality Grounding

### 2.1 Native GenOffice Editor Save APIs Used
Zero fake pipelines or simulated keystrokes were used. All saves execute through the existing native GenOffice editor engines:

1. **Docs (`.docx`)**:
   - `apps/docs/src/renderer/file-actions.ts`: Added `saveDocxForAutomation(title?: string)`.
   - Generates document via native `docx.js` / `Packer.toBlob(doc)` through `buildFullDoc()`.
   - Transmits to main process via `docs:save-new` -> written atomically to `$HOME/Documents/GenOffice/`.
   - Strict content verification check: `afterLen >= 20 && afterSize > beforeSize && childCount >= 1`.

2. **Slides (`.pptx`)**:
   - Invokes `window.slidesApi.save()` directly.
   - Triggers native `slides:save` IPC handler which serializes node elements via native `pptx-engine`.
   - Strict content verification check: `afterSlides >= 1 && afterElements >= 1 && nodes.length > 0`.

3. **Sheets (`.xlsx`)**:
   - Pre-allocates backing `.xlsx` file via `blankXlsxBuffer()` in `apps/shell/src/main/automation-view-manager.ts`.
   - Invokes native `handleSaveRef.current('save', true)` (`saveWorkbookEdits`) to flush Univer workbook changes to disk.
   - Strict content verification check: `lazyWorkbookRef.current !== null && (finalCells > 0 || finalJournal > 0) && runMutatedRef.current`.

4. **PDF (`.pdf`)**:
   - Resolved the Dual-Pathway architecture:
     - **Pathway A (In-Place Modifications)**: Backing file is opened in editor; agent tools (`insert_text`, `markup_text`) modify it; `pdfApi.save()` writes back to disk; backing file is committed as final artifact.
     - **Pathway B (Standalone `create_document`)**: Tool invokes `createAiDocument()` (headless Chromium print-to-PDF); generates standalone PDF in `defaultSaveDir()`; initial blank backing file is unlinked on disk.
   - Handshake captured via `onDocumentCreated` hook in `apps/pdf/src/renderer/ai/tools.ts`.

## 3. Structural File Integrity Verification

Implemented in `apps/shell/src/main/automation-file-validator.ts`:

- **OpenXML Verification (`JSZip`)**:
  - Validates ZIP archive headers.
  - Verifies existence of `[Content_Types].xml`.
  - For Docs: confirms `word/document.xml` exists and contains valid `<w:body>` or `<w:document>` markup.
  - For Slides: confirms `ppt/presentation.xml` exists and slide XML parts exist in `ppt/slides/slide*.xml`.
  - For Sheets: confirms `xl/workbook.xml` exists and worksheet XML parts exist in `xl/worksheets/sheet*.xml`.

- **PDF Verification (`pdf-lib`)**:
  - Parses PDF cross-reference table and trailer catalog with `PDFDocument.load(buffer)`.
  - Verifies `getPageCount() >= 1`.
  - Verifies page dimensions are valid (`width > 0 && height > 0`).

- **Cryptographic Checksum**:
  - Generates authoritative SHA-256 digest of file buffer.
  - Attached to `AutomationArtifact.content_hash`.

- **Sanitization & Non-Collision**:
  - `sanitizeTitle`: Strips directory separators, path traversal tokens (`..`, `../`), illegal OS characters, collapses whitespace, removes trailing dots.
  - `resolveSafeFileName`: Formats safe file names per document format.
  - Uses native GenOffice `uniquePathIn(defaultSaveDir(), name)` to ensure zero file overwrite collisions.

---

## 4. Deterministic Backing File Cleanup

Implemented in `apps/shell/src/main/automation-view-manager.ts` and `automation-runner.ts`:
- Backing file paths are recorded in `AutomationHandle.backingFilePath`.
- If a job fails, crashes, times out, or gets cancelled before `FILE_VALIDATED`, `releaseView()` automatically unlinks the uncommitted backing file from disk.
- Under Pathway B in PDF, the unused blank backing file is explicitly deleted upon successful commit of the standalone document.
