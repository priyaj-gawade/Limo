## 1. Executive Summary & Objective

The objective of **Phase D7.7** is to eliminate the requirement for users to manually select feature modes (`Docs`, `Slides`, `Sheets`, etc.) in the Limo Chat UI, while materially accelerating conversational chat latency and integrating Limo's native Markdown deliverable adapter strictly under the authoritative D6 transformation architecture.

### The Core Fixes Addressed (Review Feedback)
1. **Preserve D6 as the Single Routing & Execution Authority**: The Fast Intent Gate does **not** bypass D6. For generation requests, `IntentResolver` resolves the intent and target format, which feeds directly into D6 `TransformationRequest` → D6 `OutputPlan` → D6 `EngineRouter` → native execution (Markdown) or GenOffice automation runner (Office).
2. **Realistic End-to-End Latency Target**: Removed ungrounded isolated LLM claims ("<1.2s"). The success criterion is reframed around removing unnecessary tool-schema overhead (~2,200 tokens) to materially reduce end-to-end latency (Browser Send → Backend → Intent Gate → Context → LLM → Assistant Message → Browser Render), establishing empirical p50/p95 targets across cold and warm runs.
3. **Contextual Disambiguation of "table"**: Words like *"table"* do **not** automatically mean Spreadsheet. `"Create a table in Markdown"` routes to Markdown; `"Create a table in a document"` routes to Document (DOCX); an uncontextualized `"Create a table"` triggers clarification rather than guessing XLSX.
4. **Explicit Clarification Contract**: Defined a strict contract for ambiguous requests (`IntentType.AMBIGUOUS`): zero generation, zero GenOffice calls, zero file creation, and a concise conversational clarification prompt.
5. **Structured Resolution Model**: `IntentResolver` returns a strongly-typed `ResolutionResult` (`intent`, `target_format`, `confidence`, `reason`, `ambiguous_options`, `clarification_prompt`), separating classification confidence (`HIGH`, `MEDIUM`, `LOW`) from execution dispatch.

## 2. Current Architecture Findings & Latency Profiling

### 2.1 Latency Analysis Across the Full Request Lifecycle

The chat request lifecycle spans:
```text
Browser Send → Network → FastAPI Deserialization → SQLite add_user_message →
Context Hydration (SQLite + Keyword Source Scoring) → Skill Registry Match →
LLMReasoningEngine (Prompt Formatting + Tool Serialization) →
Remote Google GenAI Call → AgentLoop State Machine →
SQLite add_assistant_message → Serialization → Network → Frontend React Render
```

Empirical profiling of the individual stages on the active Limo backend:

| Stage | Component | Measured Overhead | Notes |
|---|---|---|---|
| **Local Backend Framing** | FastAPI + SQLite + Context + Skills | **~25 ms total** | Extremely fast and negligible |
| **Tool Schema Serialization** | 8 Pydantic Tools in `brain.py` | **~3 ms** | Injects ~2,180 tokens |
| **LLM Inference (With 8 Tools)** | Gemini 3.5 Flash Lite | **1.38s – 2.80s+** (cold: 14s+) | 2,201 in / 184 out (constrained decoding) |
| **LLM Inference (Fast Path - No Tools)** | Gemini 3.5 Flash Lite | **0.82s – 1.37s** | 23 in / 40 out (unconstrained text) |

### 2.2 Core Bottlenecks Identified

1. **Unconditional Tool Schema Injection**: In `backend/app/agent/brain.py`, `LLMReasoningEngine.decide` serializes 8 full function declarations into every single user turn, forcing Gemini to evaluate function-calling logits even for greetings (*"hey"*) and factual questions (*"what is an API?"*).
2. **Keyword Substring False Positives**: In `backend/app/agent/runtime.py`, substring matches (e.g. `"document about"`) caused informational queries like *"What is a document about AI?"* to mistakenly trigger GenOffice DOCX generation.
3. **Lack of D6 Authority in Runtime**: Deliverable triggers in `runtime.py` historically invoked `genoffice_client` directly, bypassing D6's `TransformationRequest`, `OutputPlanner`, and `EngineRouter`.

## 3. Dynamic Intent & Format Resolution Architecture

### 3.1 Structured Resolution Model

`IntentResolver` evaluates user input and returns a strongly-typed `ResolutionResult`:

```python
class IntentType(StrEnum):
    FAST_CHAT = "FAST_CHAT"
    GENERATE = "GENERATE"
    TRANSFORM = "TRANSFORM"
    AMBIGUOUS = "AMBIGUOUS"

class ConfidenceLevel(StrEnum):
    HIGH = "HIGH"
    MEDIUM = "MEDIUM"
    LOW = "LOW"

class TargetFormat(StrEnum):
    DOCUMENT = "document"
    PRESENTATION = "presentation"
    SPREADSHEET = "spreadsheet"
    PDF = "pdf"
    MARKDOWN = "markdown"

class ResolutionResult(BaseModel):
    intent: IntentType
    target_format: Optional[TargetFormat] = None
    confidence: ConfidenceLevel
    reason: str
    ambiguous_options: List[TargetFormat] = []
    clarification_prompt: Optional[str] = None
```

### 3.2 Decision Rules & Disambiguation Matrix

```mermaid
graph TD
    A[User Prompt] --> B{Social Greeting or Gratitude?}
    B -->|Yes| C[FAST_CHAT / LOW / "Social greeting"]
    B -->|No| D{Question or Explanation Request?}
    
    D -->|Yes without convert| E[FAST_CHAT / LOW / "Informational inquiry"]
    D -->|No| F{Passive Format Mention without Action Verb?}
    
    F -->|Yes| G[FAST_CHAT / LOW / "Passive format mention"]
    F -->|No| H{Explicit Convert / Transform?}
    
    H -->|Yes: convert X to Y| I[TRANSFORM / HIGH / target_format]
    H -->|No| J{Action Verb Present?}
    
    J -->|No and mode is none| K[FAST_CHAT / LOW / "Conversational default"]
    J -->|Yes or explicit mode| L{Format Analysis}
    
    L -->|Unspecified target / 'something'| M[AMBIGUOUS / MEDIUM / Clarify format]
    L -->|Conflicting choices / 'or' / 'maybe'| N[AMBIGUOUS / MEDIUM / Clarify options]
    L -->|Table alone without container| O[AMBIGUOUS / MEDIUM / Clarify sheet vs doc vs md]
    L -->|Single unambiguous target| P[GENERATE / HIGH / target_format]
```

### 3.3 Contextual Disambiguation of "Table"

To eliminate the defect where *"table"* was treated as an automatic synonym for Spreadsheet:
- **`"Create a table in Markdown"`** → Target: `MARKDOWN` (Confidence: `HIGH`).
- **`"Create a table in a document"`** → Target: `DOCUMENT` (Confidence: `HIGH`).
- **`"Create a spreadsheet table of Q3 sales"`** → Target: `SPREADSHEET` (Confidence: `HIGH`).
- **`"Create a table"`** (isolated without format or container context) → Intent: `AMBIGUOUS` (Confidence: `MEDIUM`). Limo responds with clarification:
  > *"Would you like me to create this table as a **spreadsheet** (Excel / XLSX), inside a **document** (DOCX), or in **Markdown**?"*

## 4. Architectural Authority: Preserving the D6 Pipeline

Under D7.7, **D6 remains the single routing and planning authority**. The runtime does not implement an ad-hoc generation engine:

```text
User Message
     │
     ▼
IntentResolver (IntentType.GENERATE, target_format=TargetFormat.MARKDOWN, HIGH)
     │
     ▼
Construct Grounded CanonicalContent (D5)
     │
     ▼
Construct D6 TransformationRequest
     ├── requested_formats = [OutputFormat.MARKDOWN]
     ├── canonical = canonical
     └── config = GenerationConfig()
     │
     ▼
D6 OutputPlanner.plan(request)
     │
     ▼
D6 OutputPlan with PlannedDeliverable
     └── route = EngineRouter.get_route(OutputFormat.MARKDOWN)
     │
     ▼
D6 EngineRouter.dispatch(route, deliverable, canonical, config)
     ├── If EngineType.NATIVE_MARKDOWN:
     │     └── NativeMarkdownAdapter.execute(...)
     │           └── Real .md file + SHA-256 + thumbnail.png + SQLite Artifact
     │
     └── If GenOffice Engine (DOCS/SLIDES/SHEETS/PDF):
           └── genoffice_client.generate_and_handoff(...)
                 └── D7 GenOffice Automation Runner + SQLite Artifact
```

### Guarantees of D6 Preservation:
1. **Single Execution Truth**: All deliverables are planned through `OutputPlanner` and routed via `EngineRouter`.
2. **Provenance & Contracts**: Metadata maintains `canonical_id`, `canonical_hash`, `deliverable_id`, and `engine_type`.
3. **Strict Markdown Isolation**: When `EngineRouter` routes `MARKDOWN`, it dispatches to `NativeMarkdownAdapter`, never touching GenOffice APIs or Electron processes.

## 5. Explicit Clarification Contract

For ambiguous or conflicting user requests, the system adheres to a strict formal contract:

```text
Contract: Ambiguity Clarification
Trigger: ResolutionResult.intent == IntentType.AMBIGUOUS or confidence == ConfidenceLevel.MEDIUM
```

### Invariants:
1. **Zero Artifact Creation**: No `Artifact` record is inserted into SQLite.
2. **Zero Engine Invocations**: Neither GenOffice automation nor `NativeMarkdownAdapter` is called.
3. **Zero Files on Disk**: No physical files (`.docx`, `.pptx`, `.xlsx`, `.pdf`, `.md`) are written to storage.
4. **Concise Conversational Turn**: The assistant persists a clean conversational turn with `artifact_ids=[]`, prompting the user for the necessary decision.

### Standard Clarification Formats:
- **Disjunctive Choice**: *"I would be happy to create that for you! Would you prefer a **document** (Word / DOCX) or a **presentation** (slide deck / PPTX)?"*
- **Table Without Container**: *"Would you like me to create this table as a **spreadsheet** (Excel / XLSX), in a **document** (DOCX), or formatted in **Markdown**?"*
- **Unspecified Deliverable**: *"I'd love to help! What kind of deliverable would you like to create? (For example: a document, presentation, spreadsheet, PDF memo, or Markdown file?)"*

| **G1: Ambiguous Formats** | User expresses multiple disjunctive formats | *"Make something for my report, maybe slides or a document."* | `AMBIGUOUS` / `MEDIUM` | Asks clarifying question: document vs presentation. Zero generation. |

## 7. UI Architecture & Seamless Mode Transition

  `"Ask anything, or say 'Create a presentation / doc / spreadsheet / markdown...'"`

## 10. Success Criteria

1. **D6 Architectural Integrity**: D6 remains the single planning, configuration, and routing authority; no ad-hoc bypassing in runtime.
2. **Material Latency Reduction**: Fast-path removes unnecessary tool-schema overhead (~2,200 tokens eliminated), materially reducing end-to-end chat latency across warm and cold runs.
