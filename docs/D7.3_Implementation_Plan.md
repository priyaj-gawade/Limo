## 1. Executive Summary & Core Objective

The objective of **Phase D7.3** is to harden the background GenOffice automation engine built in D7.1 and D7.2 into a **production-grade, leak-free, self-healing runtime**:

```text
Incoming Limo Request (POST /api/v1/generate)
       ↓
FIFO Queue (Concurrency Ceiling = 1)
       ↓
Hidden Background WebContentsView (1280×800 offscreen viewport, setVisible(false))
       ↓
Handshake & Readiness Guard (15s RENDERER_INIT_TIMEOUT)
       ↓
Native AgentLoop Execution (Bounded AGENT_EXECUTION_TIMEOUT: 10s min, 300s def, 1800s max)
       ↓
Completion / Cooperative Cancel / Forceful Fallback / Crash / Timeout
       ↓
Unified Convergent Teardown (single finally block: view detach, webContents close, temp cleanup)
       ↓
Terminal Job Transition (COMPLETED / CANCELLED / FAILED only after teardown succeeds)
       ↓
Queue Drained -> Next Queued Job Runs Cleanly
```

## 2. Resolution of the 4 Must-Fix Review Points

### 2.1 MUST-FIX #1: Strict "Forceful View Destruction" Semantics & Timing
- **The Invariant**: A job is **never** marked `cancelled` while the runner or hidden view may still be executing.
- **The Execution Chain**:
  1. `POST /api/v1/jobs/:id/cancel` sets `job.cancellation_requested = true` (HTTP 202).
  2. Runner sends `automation:agent-cancel` IPC to the renderer.
  3. Renderer receives signal and calls `loop.cancel()`.
  4. **Cooperative Window (5,000 ms grace period)**:
     - If renderer `onDone({ cancelled: true })` emits `automation:agent-cancelled` within 5s, cooperative cancellation succeeds.
  5. **Forceful Escalation (5s grace expires)**:
     - If the renderer does not signal cancelled within 5s (e.g. stalled script), the runner escalates to forceful view destruction via `viewManager.destroyActiveView()`.
  6. **Convergent Teardown**:
     - The runner enters the unified `finally` block: detaches the view, closes the webContents, unlinks temp files, clears intervals/timers, and resets `activeHandle = null`.
  7. **State Transition**:
     - **Only after teardown completely finishes** does `finalizeCancellation(jobId)` transition `job.status = 'cancelled'`.
     - `drainQueue()` is called only after the previous job is 100% dead and cleaned up.

### 2.2 MUST-FIX #2: Scoped & Empirically Verified `backgroundThrottling` Handling
- **Principle**: Do not apply blanket, speculative Electron configuration changes across shared application factories.
- **Current State**:
  - `apps/docs` and `apps/sheets` already explicitly pass `backgroundThrottling: false` in their view factories.
  - `apps/slides` and `apps/pdf` omit it, but D7.2 live probe completed both slides and PDF runs successfully in hidden views.
- **D7.3 Action**:
  - Keep generic editor factories untouched.
  - Test and verify whether Slides and PDF exhibit any timer throttling latency under hidden execution.
  - Only configure `backgroundThrottling: false` where verified necessary, avoiding speculative global changes.

### 2.3 MUST-FIX #3: Bounded Configurable Range for `timeout_seconds`
- **Bounds**:
  - Minimum: `10` seconds (`MIN_TIMEOUT_SECONDS = 10`)
  - Default: `300` seconds (`DEFAULT_TIMEOUT_SECONDS = 300`)
  - Maximum Hard Ceiling: `1800` seconds / 30 minutes (`MAX_TIMEOUT_SECONDS = 1800`)
- **Validation Rule**:
  - In `automation-validator.ts`, validate `options.timeout_seconds`:
    If present, it must be a finite number between `10` and `1800`.
    Reject values `< 10` or `> 1800` or non-integers with HTTP 400 (`INVALID_TIMEOUT_RANGE`).

### 2.4 MUST-FIX #4: Parent `shellWindow` Closure Ownership & Safe Teardown
- **Problem**: If the user closes GenOffice while a background automation job is generating, child view cleanup could race with Electron window destruction, causing crashes or attempted access to a destroyed window.
- **Strict Ownership Sequence**:
  ```text
  shellWindow emits 'close' or 'closed'
         ↓
  AutomationViewManager.onWindowClosing() triggers
         ↓
  1. Abort active runner promise with Error('SHELL_WINDOW_CLOSED')
  2. Forcibly detach and close hidden WebContentsView (guarded by !isDestroyed())
  3. Clean up any temporary files (PDF buffers)
  4. Clear activeHandle = null
  5. Mark active job status: failed (code: 'SHELL_WINDOW_CLOSED')
  6. Cancel remaining queued jobs with 'SHELL_WINDOW_CLOSED'
  7. Do NOT attempt further window or webContents operations
  ```

## 3. Unified Convergent Lifecycle Architecture

Every execution path—success, cancellation, timeout, crash, or window close—converges into a single, deterministic teardown path:

```text
[Job Enqueued & Started]
          │
          ▼
       STARTING ──────────── (Init Timeout: 15s) ───────────┐
          │                                                 │
          ▼                                                 │
    RUNNING_AGENT                                           │
          │                                                 │
          ├─────────────────────────┬───────────────────────┤
          │                         │                       │
     (Agent Done)          (Cancel Requested)       (Error / Crash / Timeout / Close)
          │                         │                       │
          │                  loop.cancel()                  │
          │                         │                       │
          │                  [Grace Period 5s]              │
          │                   /           \                 │
          │             Cooperative    Forceful Kill        │
          │               Signal      (5s expired)          │
          │                   \           /                 │
          ▼                     ▼       ▼                   ▼
     AGENT_COMPLETED        CANCEL SIGNAL               ERROR SIGNAL
          │                         │                       │
          └─────────────────────────┼───────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│             CONVERGENT UNIFIED TEARDOWN (try ... finally)              │
│ 1. Clear execution timeout, cancel grace timer, progress intervals     │
│ 2. Detach view from shellWindow.contentView (if window not destroyed)  │
│ 3. Close view.webContents (if webContents not destroyed)               │
│ 4. Unlink temporary PDF buffer from disk (if format === 'pdf')        │
│ 5. Clear activeHandle = null, clear pending resolvers & ready sets     │
│ 6. Release activeJobId = null                                          │
└────────────────────────────────────────────────────────────────────────┘
                                    │
          ┌─────────────────────────┼────────────────────────────┐
          ▼                         ▼                            ▼
      COMPLETED                 CANCELLED                      FAILED
          │                         │                            │
          └─────────────────────────┴────────────────────────────┘
                                    │
                                    ▼
                         drainQueue() -> Next Job
```

## 4. Architectural Boundaries (Strict Separation)

| Capability | Phase D7.1 (Queue) | Phase D7.2 (AgentLoop) | Phase D7.3 (Lifecycle — THIS PHASE) | Phase D7.4 (Save & Verify) | Phase D7.5 (Limo Handoff) |
|---|---|---|---|---|---|
| **View Execution** | N/A (No views) | Single hidden `WebContentsView` | Bounded lifecycle, crash/leak-safe teardown | Same | Same |
| **Agent Execution** | N/A | Native `AgentLoop.run()` | Same + execution timeout & cancel handshake | Same | Same |
| **Execution State** | `queued` | `STARTING` → `RUNNING_AGENT` → `AGENT_COMPLETED` | Unified convergent teardown | Transitions to `COMPLETED` | Artifact registered |

| **File Creation** | **NONE** | **NONE** (`artifact: null`) | **NONE** (`artifact: null` maintained) | **NATIVE SAVE** (`saveDocxNew`, etc.) | Read saved file metadata |
| **Content Validation** | **NONE** | Mutation signals only | Mutation signals only | Semantic integrity check | Verify file integrity |
